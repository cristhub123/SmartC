CAMBIOS — Etapa A de PLAN_CATEGORIAS_SUBCATEGORIAS.md (modelo de datos), 2026-09-06
=========================================================================

Alcance de esta entrega: SOLO modelo de datos, sin UI nueva (Etapa A
del plan de categorías/subcategorías). No hay nada distinto para ver
todavía en la app — el filtro y el admin de categorías funcionan
exactamente igual que antes.

QUÉ CAMBIÓ
------------
- js/config.js: CAT pasa de `label` string plano a `label`
  multi-idioma ({es, en, pt}) + `subcategories: {}` anidado (vacío en
  las 7 categorías por ahora — qué categoría pasa a ser subcategoría
  de cuál queda pendiente, es una decisión tuya desde el admin una
  vez exista esa pantalla). Se conservan los 7 ids tal cual
  (food/culture/music/bar/art/historic/shop) para no romper los pines
  ya guardados. Nueva variable `languageFieldsCount` (default 3), para
  el candado de cantidad de idiomas que se va a construir más
  adelante.
- js/categories.js: nueva función `getCatLabel(cat, lang)` — única
  forma correcta de leer el label de una categoría como texto (con
  fallback a español si falta un idioma, igual que ya hace el resto
  de la app). Se actualizaron todos los lugares de este archivo que
  mostraban el label de una categoría (lista de categorías del admin,
  activar/desactivar, eliminar, barra de filtros, selector de
  categorías de un pin) para usar esta función. Crear una categoría
  nueva desde el admin ahora arma el mismo tipo de dato que las
  categorías base (con sus 3 idiomas y su casillero de subcategorías).
- js/content-import.js, js/app.js, js/admin.js, js/data-io.js,
  js/pin-adjust.js: mismo ajuste — todo lugar que mostraba o guardaba
  el nombre de una categoría (buscador, listado de Lugares,
  export/import JSON, alta/edición de pin, importación masiva por
  texto) usa ahora la misma función nueva, para que nada se rompa ni
  muestre texto raro.
- js/settings-sync.js: el guardado de categorías en Firestore ahora
  guarda la categoría base completa (label + subcategorías + activo),
  no solo si está activada o no como antes — necesario porque ahora
  el label es editable. Si abrís la app y todavía tiene el guardado
  viejo, lo sigue leyendo bien (no se pierde nada).
